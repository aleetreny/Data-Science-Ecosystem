Probabilistic Cancer Classification via RNA-Seq Data

Multiclass classification of tumor types using RNA-Seq data and probabilistic learning models (LDA, QDA, Naive Bayes).
Author

Alejandro Treny

Published

August 18, 2026

Introduction

This project focuses on applying Statistical Learning techniques for the multiclass classification of different cancer types using gene expression data (RNA-Seq). The ability to distinguish between tumor subtypes at the molecular level is fundamental for precision medicine, enabling more accurate diagnoses and personalized treatments.

The Dataset

We utilize an extraction of the TCGA Pan-Cancer (PANCAN) dataset, available at the UCI Machine Learning Repository. This dataset consists of gene expression levels measured using the Illumina HiSeq platform.

Key Characteristics:

  • Samples (Instances): 801 individuals, all diagnosed with a type of tumor.
  • Variables (Genes): 20,531 dimensions, posing the challenge of the “curse of dimensionality.”
  • Classes (Labels): 5 distinct tumor types:
    • BRCA: Breast Invasive Carcinoma.
    • KIRC: Kidney Renal Clear Cell Carcinoma.
    • COAD: Colon Adenocarcinoma.
    • LUAD: Lung Adenocarcinoma.
    • PRAD: Prostate Adenocarcinoma.

Project Objective

The primary goal is not to identify the genetic causes of cancer (comparing healthy vs. sick individuals), but rather to develop a model capable of correctly classifying the origin of tumor tissue based solely on its gene expression profile.

Methodology and Models

To achieve a robust classification, we will adhere to the Probabilistic Learning framework covered in the course curriculum. Specifically, we will implement and compare the following models suitable for multiclass classification:

  1. Linear Discriminant Analysis (LDA): A generative method assuming Gaussian distributions with a common covariance matrix.
  2. Quadratic Discriminant Analysis (QDA): A more flexible extension of LDA allowing for class-specific covariance matrices.
  3. Naive Bayes: A probabilistic classifier assuming independence between features (genes).
  4. Multinomial Logistic Regression: An extension of the standard binary logistic regression for multiple classes (used as a baseline).

Statistical Challenge: High Dimensionality (\(p \gg n\))

Our dataset contains 20,531 genes (\(p\)) but only 801 samples (\(n\)). This presents a critical problem for models like LDA and QDA, which require computing covariance matrices. Since \(p > n\), these matrices are not invertible (singular), and the models will mathematically fail.

To solve this, we must perform Dimensionality Reduction before modeling. We will use Principal Component Analysis (PCA) to project the gene space into a smaller set of uncorrelated components that capture the majority of the variance. As part of this process, genes with zero variance (constant across all samples) are removed, since they carry no discriminative information and cause numerical issues during scaling.

Evaluation Framework

Following the best practices for Model Evaluation, we will rigorously validate our results using:

  • Stratified Train/Test Split (80/20): PCA is fitted exclusively on the training set, and the test set is projected independently to prevent data leakage.
  • 10-Fold Cross-Validation: Applied within the training set to tune the number of principal components and confirm the stability of our error estimates.
  • Confusion Matrices: To verify performance across all 5 cancer types on the held-out test set.
  • Result Validation: Permutation tests and integrity checks to confirm the results are not artifacts.
  • Metrics: We will use Accuracy and Kappa (to account for random chance agreement) as our primary metrics.

Principal Component Analysis (PCA)

As established in the introduction, the raw gene space (\(p = 20{,}531\)) far exceeds the number of samples (\(n = 801\)), making direct application of LDA, QDA, or logistic regression impossible. PCA allows us to project the data into a lower-dimensional space of uncorrelated components while retaining the majority of variance.

Crucially, PCA is fitted only on the training set to avoid data leakage. The test set is then projected onto the same principal components.

Code 
library(factoextra)

# Remove zero-variance genes (computed on training set)
train_gene_cols <- train_data |> dplyr::select(starts_with("gene_"))
train_var <- apply(train_gene_cols, 2, var)
nonzero_var_genes <- names(train_var[train_var > 0])

# Fit PCA on training data only
pca_train <- train_data |> dplyr::select(all_of(nonzero_var_genes))
pca_result <- prcomp(pca_train, center = TRUE, scale. = TRUE)

# Project test data using the training PCA
pca_test_scores <- predict(pca_result, newdata = test_data |> dplyr::select(all_of(nonzero_var_genes)))

Model Training and Evaluation

We now train the four probabilistic classifiers outlined in the introduction: LDA, QDA, Naive Bayes, and Multinomial Logistic Regression. PCA, centring and scaling are fitted independently inside every resampling fold; otherwise validation folds would influence their own feature representation.

To understand how the number of principal components affects performance, we sweep over several values: 5, 10, 20, 50, 100, and 159 (the number needed to capture 80% of the training variance).

Note that QDA requires each class-specific covariance matrix to be invertible, so the number of PCs must be smaller than the size of the smallest class in the training set. We therefore limit QDA to a maximum of 50 PCs.

Code 
library(MASS)
library(nnet)
library(e1071)
library(naivebayes)

pc_counts <- c(5, 10, 20, 50, 100, 159)
x_train <- train_data |>
  dplyr::select(all_of(nonzero_var_genes))
y_train <- train_data$Class

# The x/y interface avoids expanding a 20k-gene formula.  To avoid fitting the
# same PCA 22 times per fold, each fold fits the full 159-PC transformation once
# on its analysis subset, then every classifier consumes the required prefix.
# This preserves fold isolation: validation samples never affect centring,
# scaling, zero-variance filtering, or PCA.
set.seed(42)
fold_indices <- createFolds(y_train, k = 10, returnTrain = FALSE)
max_pcs <- max(pc_counts)

fold_scores <- lapply(fold_indices, function(validation_idx) {
  analysis_idx <- setdiff(seq_len(nrow(x_train)), validation_idx)
  transformation <- preProcess(
    x_train[analysis_idx, ],
    method = c("zv", "center", "scale", "pca"),
    pcaComp = max_pcs
  )

  list(
    train_x = predict(transformation, x_train[analysis_idx, ])[, seq_len(max_pcs), drop = FALSE],
    valid_x = predict(transformation, x_train[validation_idx, ])[, seq_len(max_pcs), drop = FALSE],
    train_y = y_train[analysis_idx],
    valid_y = y_train[validation_idx]
  )
})

predict_fold <- function(model_name, fold, k) {
  train_x <- fold$train_x[, seq_len(k), drop = FALSE]
  valid_x <- fold$valid_x[, seq_len(k), drop = FALSE]

  if (model_name == "LDA") {
    predict(lda(x = train_x, grouping = fold$train_y), valid_x)$class
  } else if (model_name == "QDA") {
    predict(qda(x = train_x, grouping = fold$train_y), valid_x)$class
  } else if (model_name == "Naive Bayes") {
    fit <- naive_bayes(x = train_x, y = fold$train_y)
    predict(fit, newdata = valid_x)
  } else if (model_name == "Multinomial LogReg") {
    set.seed(42)
    train_md <- as.data.frame(train_x)
    train_md$Class <- fold$train_y
    fit <- multinom(Class ~ ., data = train_md, trace = FALSE, MaxNWts = 5000)
    predict(fit, newdata = as.data.frame(valid_x))
  } else {
    stop("Unsupported model: ", model_name)
  }
}

evaluate_configuration <- function(model_name, k) {
  predictions <- unlist(lapply(fold_scores, predict_fold, model_name = model_name, k = k))
  reference <- unlist(lapply(fold_scores, `[[`, "valid_y"))
  comparison <- confusionMatrix(
    factor(predictions, levels = levels(y_train)),
    factor(reference, levels = levels(y_train))
  )

  tibble(
    PCs = k,
    Model = model_name,
    Accuracy = unname(comparison$overall["Accuracy"]),
    Kappa = unname(comparison$overall["Kappa"])
  )
}

models_to_evaluate <- c("LDA", "Naive Bayes", "Multinomial LogReg")
results_list <- list()

for (k in pc_counts) {
  for (model_name in models_to_evaluate) {
    results_list[[paste(model_name, k, sep = "_")]] <- evaluate_configuration(model_name, k)
  }

  # QDA needs more samples per class than retained components.
  if (k <= 50) {
    results_list[[paste("QDA", k, sep = "_")]] <- evaluate_configuration("QDA", k)
  }
}

results_all <- bind_rows(results_list)

The training loop fits a total of 22 models (4 classifiers x 6 PC counts, minus QDA for 100 and 159 PCs). Each model is evaluated via 10-fold cross-validation within the training set, producing both Accuracy and Kappa as performance metrics. Kappa is particularly useful here because it adjusts for the class imbalance we observed earlier, giving a more honest picture of whether the model is genuinely learning the class boundaries or simply exploiting the prior probabilities.

Per-Model Confusion Matrices (Test Set)

To get an honest estimate of generalization performance, we now evaluate each model on the held-out test set. For each classifier, we select the best PC count from cross-validation, retrain on the full training set, and predict on the test set.

Code 
# Find best PC count per model (from CV results)
best_per_model <- results_all |>
  group_by(Model) |>
  arrange(desc(Accuracy), desc(Kappa)) |>
  slice_head(n = 1) |>
  ungroup()

# Map model names to caret method names (used in CV loop above)
method_map <- c(
  "LDA" = "lda",
  "QDA" = "qda",
  "Naive Bayes" = "naive_bayes",
  "Multinomial LogReg" = "multinom"
)

# Retrain each best model on full training set, predict on test set
per_model_cms <- list()

for (i in seq_len(nrow(best_per_model))) {
  row <- best_per_model[i, ]
  k <- row$PCs
  model_name <- row$Model
  
  # Training data in PC space
  train_md <- as_tibble(pca_result$x[, 1:k]) |>
    mutate(Class = train_data$Class)
  
  # Test data in PC space (projected using training PCA)
  test_md <- as_tibble(pca_test_scores[, 1:k])
  
  set.seed(42)
  
  # Fit directly to avoid caret tuneGrid issues with method = "none"
  if (model_name == "LDA") {
    fit <- lda(Class ~ ., data = train_md)
    test_preds <- predict(fit, newdata = test_md)$class
  } else if (model_name == "QDA") {
    fit <- qda(Class ~ ., data = train_md)
    test_preds <- predict(fit, newdata = test_md)$class
  } else if (model_name == "Naive Bayes") {
    fit <- naive_bayes(Class ~ ., data = train_md)
    test_preds <- predict(fit, newdata = test_md)
  } else if (model_name == "Multinomial LogReg") {
    fit <- multinom(Class ~ ., data = train_md, trace = FALSE)
    test_preds <- predict(fit, newdata = test_md)
  }
  
  per_model_cms[[model_name]] <- list(
    cm = confusionMatrix(test_preds, test_data$Class),
    k = k,
    name = model_name
  )
}

Result Validation

Very high accuracy can be a symptom of data leakage or other methodological errors. The following checks assess selected leakage risks, but they do not replace repeated evaluation on an external cohort.

Why Are These Results So High?

High scores can be plausible for this benchmark because the five labels arise from distinct tissues, but that explanation is a hypothesis about this dataset rather than a clinical-performance guarantee. The reported checks reduce common leakage risks; independent cohorts and repeated splits would be required to assess robustness.

Conclusion

This study evaluates probabilistic classifiers combined with PCA for five cancer types (BRCA, KIRC, COAD, LUAD and PRAD). The reported values in the generated tables use a train/test split, train-only PCA, and fold-isolated cross-validation for PC selection. They are evidence about this dataset and split, not proof of clinical generalisation.

Key Findings

  1. A rigorous train/test split is essential. Computing PCA on the full dataset before cross-validation introduces data leakage, which can inflate accuracy estimates. By fitting PCA only on the training set (642 samples) and projecting the test set (159 samples) independently, we obtain honest generalization estimates.

  2. PCA is essential, not optional. With \(p = 20{,}531\) genes and only \(n = 801\) samples, direct application of LDA, QDA, or logistic regression is mathematically impossible. PCA reduces the feature space while preserving the discriminative structure, as confirmed by the clear class separation visible in the first few principal components.

  3. Model ranking should follow the rendered training-CV and held-out tables. PCA coordinates are orthogonal, but that property does not guarantee the covariance assumptions of LDA or QDA.

  4. Multinomial Logistic Regression is a discriminative comparison that learns decision boundaries in the selected PCA space; its current performance is displayed in the generated result tables.

  5. Naive Bayes is evaluated across the same PC grid. Its independence assumption is not guaranteed by PCA, so any trend with component count should be read from the current cross-validation curve rather than a fixed narrative value.

  6. The EDA was instrumental in guiding modeling decisions. The bimodal expression distribution and the large number of zero-variance genes motivated the filtering step before PCA. The ANOVA analysis confirmed that individual genes carry strong tissue-specific signals, and the correlation heatmap justified the use of PCA to handle multicollinearity.

  7. The integrity checks are safeguards, not proof of generalisation. The fold isolation, train/test disjointness and sanity checks reduce common leakage risks; an external cohort would still be required before making clinical-performance claims.

Limitations and Future Work

  • The dataset is relatively clean and well-separated, which partly explains the strong results. Real clinical scenarios may involve noisier data, subtler cancer subtypes, or mixed tissue samples.
  • More advanced methods such as regularized discriminant analysis, support vector machines, or ensemble methods could be explored, although the current models already achieve very high performance on this dataset.
  • A biological interpretation of the top PCA loadings and ANOVA genes could provide insights into the molecular pathways distinguishing each cancer type, connecting the statistical results to domain knowledge.

Annex: Nonlinear Dimensionality Reduction (UMAP)

Motivation

Throughout this study, we have relied on PCA for dimensionality reduction. PCA is a linear method: it finds the directions of maximum variance and projects the data onto them. This is ideal for modeling (uncorrelated features, interpretable loadings), but linear projections can fail to capture complex, nonlinear relationships between samples when visualizing them in just two dimensions.

UMAP (Uniform Manifold Approximation and Projection) is a nonlinear dimensionality reduction technique that constructs a topological representation of the high-dimensional data and optimizes a low-dimensional layout that preserves both local neighborhood structure and, to some extent, global distances between clusters. Compared to the older t-SNE algorithm, UMAP is faster, better preserves global structure, and produces embeddings where inter-cluster distances are more meaningful.

Important caveat: UMAP is used here exclusively for visualization. All classification models in this study use PCA scores as features. UMAP embeddings are not suitable as model inputs because the transformation is nonparametric, non-invertible, and sensitive to hyperparameters.

We fit UMAP on the first 50 PCA scores of the training set (a common practice to denoise the input before nonlinear projection) and then project the test set onto the same embedding.

The side-by-side comparison highlights the complementary strengths of each method:

  • PCA (left) preserves global variance directions. KIRC separates clearly along PC1, and PRAD along PC2, but BRCA, COAD, and LUAD form an overlapping cloud in the center. This is a consequence of PCA being a linear projection: it cannot “unfold” nonlinear structure in just two dimensions (though it works well for classification when using 10-50 PCs).
  • UMAP (right) sacrifices the linear interpretability of PCA axes but recovers the local neighborhood structure of the data, pulling all five classes into distinct clusters. Both methods agree on the same fundamental conclusion: the five cancer types occupy distinct regions of gene expression space. PCA captures this through orthogonal variance directions (which are ideal for classification), while UMAP reveals it through topology-preserving nonlinear embedding (which is ideal for visualization).
